# Themes

## Theme styles (classic/neo/glass/titanium/spatial) live in data-theme, orthogonal to .dark
Five switchable styles: Classic (all of app.css), Neumorphic (themes/neo.css), Glass (themes/glass.css), Titanium (themes/titanium.css — machined metal), Spatial (themes/spatial.css — 3D floor/tilt), selected by `data-theme` on <html> and independent of Flux's `.dark` class, so each has light+dark. Switcher = `<x-theme-style-switcher />` (under the appearance control in all 4 user menus; swatch styles in themes/switcher.css) → Alpine store `themeStyle` in resources/js/theme-style.js, persisted in localStorage `optifin.theme-style`; an inline script in partials/head.blade.php sets it pre-paint. Adding a style = new themes/*.css + its @import in app.css + THEME_STYLES in theme-style.js + the list in head.blade.php + the classic gate in app.css + a swatch.
Traps: (1) wire:navigate REMOVES <html> attributes the server HTML lacks, so data-theme is re-applied in `livewire:navigating` → `onSwap` (runs before paint) — never render data-theme server-side in only some layouts. (2) The classic unlayered neumorphism block in app.css is gated with `:root:not([data-theme="neo"], [data-theme="glass"], [data-theme="titanium"], [data-theme="spatial"])`; keep new classic unlayered box-shadow rules gated too or they leak into the other styles. (3) Flux modals with scroll="body" make the <dialog> full-viewport (card is `[data-flux-modal-content]`) — only style `dialog.rounded-xl` as a card. (4) Theme CSS targets hooks: `data-flux-variant` on flux buttons (published stub), `.app-topbar`, `.kanban-column`, `.kanban-card`; keep them when editing those views. (5) Neo shadows are 4-layer [outer dark, outer light, inset dark, inset light] so raised↔pressed interpolate — keep that shape for new states. (6) resources/js/theme-pointer.js writes `--ptr-x/-y` (and, for Spatial only, `--tilt-x/-y`) inline on the hovered surface; Titanium/Spatial paint their glint/spotlight as background layers reading those vars plus registered `@property` colors (`--ti-glint`, `--sp-spot`, `--sp-rim-spot`) so they fade — no pseudo-elements, no stacking contexts. A var composed from another var must be declared on the element itself, not :root, or animating the inner one does nothing. (7) flux:menu turns every <a>/<button> inside it into role="menuitem" that closes the menu on click — the switcher swatches are therefore <span role="radio"> with a roving tabindex, not buttons.
