# Api

## Lead Management module ported from OpticoreLeadManagementHub
The Lead Management module (Lead, LeadSource, LeadAssignment, LeadStatusLog, LeadNote models; LeadSourceType/LeadStatus/LeadPriority/LeadDistributionMode/AutoDistributionMethod enums; LeadAssignmentService; the webhook capture flow in app/Http/Controllers/Api/LeadWebhookController.php; the IMAP email-polling FetchEmailLeads command + ProcessEmailLeadSource job) is ported from a sibling project, `/media/rashed/HDD Drive 1/OpticoreLeadManagementHub` (Laravel+Inertia/React), adapted onto this project's Blade/Livewire stack and its Tenant/TenantUser/Role/Module/Permission foundation. Lead sources are configured by the Platform Admin under `/admin/clients/{tenant}/lead-sources` (App\Livewire\Platform\Clients\LeadSources) — the tenant side (`/lead-sources`) is read-only, matching the reference app's split. Webhook URLs are keyed by `tenant_code` (not a separate slug column). If building another ERP module with a similar "external capture + per-client config" shape, check that reference project first — it likely already solved it.

## Facebook Lead Ads shares Messenger's webhook URL and Page
Meta delivers `leadgen` change events (Facebook Lead Ads / Instant Forms) to the same Page-level webhook subscription as Messenger `messaging` events — both hit `/api/webhook/facebook/{tenant_code}`, no separate URL. `LeadSourceType::FacebookLeadAds` is its own LeadSource row (own Page ID/token/verify_token/app_secret entry, separate from FacebookMessenger) so a tenant can configure either without the other. `LeadWebhookController::facebookMessenger()` resolves the Messenger source lazily (only when a `messaging` event actually needs it) specifically so a Lead-Ads-only tenant isn't 404'd; `verifyFacebook()` and the `verify.meta.signature` middleware both fall back across `facebook_messenger,facebook_lead_ads` for the same reason. Lead Ads dedup is by `source_data->leadgen_id` (app-level lookup, same non-unique-constraint pattern Messenger/Instagram already use for their sender-id dedup) — a duplicate webhook delivery is skipped, not re-fetched, since a lead ad submission is immutable once made. A `leads_retrieval` fetch failure (Graph API error code 100 / subcode 33) still creates a minimal lead keyed by `leadgen_id` rather than dropping the submission.
