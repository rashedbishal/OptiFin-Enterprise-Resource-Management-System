# Partials

## Full-page Lead view (show.blade.php) has its own dedicated partials — don't touch the ones shared with show-panel.blade.php
`show.blade.php` (the Client Admin's full `/leads/{lead}` page) was redesigned into: a hero banner (`partials/lead-hero.blade.php` — identifier/status/priority badges, company-or-name heading, Deal Value + Lead Score stat boxes, delete button), a read-only `partials/pipeline-stepper.blade.php` (visual only — clicking a stage does nothing; the real status change is still the separate Status card), an Overview/Activity Timeline toggle driven by `Show::$activeTab` (plain public property, same pattern as the existing `$bodyView` toggle — no new Livewire wiring), and two new read-only cards `partials/contact-info-card.blade.php` / `partials/pipeline-attributes-card.blade.php` that replace showing `company-form.blade.php`/`deal-form.blade.php` on this page only.

**Why:** `header.blade.php`, `company-form.blade.php`, `deal-form.blade.php`, `detail-card.blade.php`, `activity-card.blade.php`, `note-form.blade.php`, `status-form.blade.php`/`status-badges.blade.php`, and `assignment-form.blade.php` are all still shared with `show-panel.blade.php` (the Kanban flyout, Client User view) — none of their content/markup was changed, only which of them `show.blade.php` chooses to include and where. Editing any of those shared files' content affects the flyout too. The one exception is `note-form.blade.php`, which gained an optional `$compact` param (default `false`, so the flyout's call site is pixel-identical to before) — same established pattern `header.blade.php`/`detail-card.blade.php`/`activity-card.blade.php` already used for this exact dual-use need, so extend that param rather than forking a new file if another shared partial needs a size variant here.

**Current tab contents:** Overview & Intel = Contact Information + Pipeline Attributes (2-col grid) + the message/attachment card (`detail-card.blade.php`). Activity Timeline = a 2-col grid: the Activity card on the left; on the right, a `flex flex-col justify-between` stack of Add Note (compact) → the merged Status & Assignment card, moved there from Overview at the user's request so Activity's height (variable, capped by its own `max-h-96`) and the right column balance out via CSS Grid's default `align-items: stretch` + `justify-between`, not by giving any individual card `h-full`/`flex-1` (that combination inside a grid row already broke these same cards once before — see [[Don't combine flex-1 + h-full inside a CSS Grid row with align-items:stretch]]). If asked to move cards between tabs again, keep using that stretch+justify-between technique, not height hacks on the cards themselves.

**Status & Assignment is merged only on this page.** `partials/status-assignment-form.blade.php` (full-page only) combines the Status/Priority fields and the Assignee field into one form with one "Update" button, wired to `Show::updateStatusAndAssignment(LeadAssignmentService $assignmentService)`. That method just calls the existing `updateStatus()`/`assign()` methods conditionally (only the half the viewer's `canUpdate()`/`canAssign()` gate allows), unmodified — so each half keeps its own validation, activity logging, and `LeadStatusChanged`/`LeadUpdated` Reverb broadcasting exactly as before (verified in `LeadStatusAssignmentMergedFormTest.php`); a single save can still surface up to two toasts. `status-form.blade.php`/`assignment-form.blade.php` are untouched and still render as two separate cards/buttons on the Kanban flyout (`show-panel.blade.php`) — don't merge them there too unless asked.

**How to apply:** If asked to further tweak the full-page Lead view's layout, edit `show.blade.php` or the dedicated partials above. Don't add fields/text into the shared partials just to make this page match a mockup — add a new dedicated partial (or an opt-in `$compact`-style param) instead, like this change did. The Pipeline Attributes card deliberately labels the source-channel row "Source Channel:", not "Lead Source:", to avoid colliding with `Lead::lead_source` (the distinct manual-entry-only field, see [[Lead::lead_source is manual-entry-only metadata, distinct from source() relation]]).
