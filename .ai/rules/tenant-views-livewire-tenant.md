# Tenant Views Livewire Tenant

## Notification bell: instant-open via Alpine, skeleton via wire:loading — and a real x-show/static-class gotcha
The bell dropdown used to be a single server round trip: `$open` toggled server-side, and the dropdown only existed in the DOM once that returned (`@if ($open)`). Restructured so clicking shows the dropdown shell instantly (`x-data="{ open: false }"`, `x-on:click="open = ! open"`, `x-show="open"` — no server round trip needed for visibility at all now) while `wire:click="openNotifications"` fires in parallel purely to fetch data, revealed via the same `wire:loading.class="!hidden"` skeleton technique used everywhere else. `notifications()` is gated behind `$notificationsLoaded` (starts false) so it stays lazy — never queried on a plain page load where the bell is never opened, matching the original behavior; `unreadCount()` is NOT gated, it must stay accurate on every page load regardless of whether the dropdown has ever been opened. `toggle()`/`close()`/the old `$open` property were removed entirely — visibility is 100% Alpine-local now.

**Real gotcha hit and fixed**: initially added a static `class="hidden"` on the dropdown box as a "safe pre-hydration default," reasoning (wrongly) that Alpine's inline-style toggling would override a plain class-based `display:none` regardless of source order. It doesn't — confirmed via direct DOM inspection (Playwright): Alpine's `x-show`, when paired with `x-transition` (as this dropdown is), shows an element by clearing its OWN inline `display` back to an **empty string** (falls back to the CSS cascade) rather than forcing a specific value like `display:block`. An empty inline style doesn't win against anything — the competing class-based `.hidden{display:none}` rule just keeps applying. Fix: no static class at all on the dropdown box, matching how `x-dropdown-select`'s panel and `x-date-picker`'s popup already do it (`x-show="open"` alone, no competing class) — x-show's own default-hidden behavior on initialization is sufficient. If a future skeleton/dropdown/modal needs to combine `x-show`+`x-transition` with a "hidden until Alpine hydrates" safety net, don't reach for a static `hidden`/`!hidden` class — it doesn't work with this combination.

This module's other 4+ `x-cloak` usages (`date-picker.blade.php`, `datetime-picker.blade.php`, `dropdown-select.blade.php`, `two-factor-challenge.blade.php`) may have the same class of issue if any of them pair `x-cloak` with `x-transition` the same way — no global `[x-cloak] { display: none !important }` CSS rule exists anywhere in this app's stylesheets, so `x-cloak` on its own isn't actually preventing FOUC in this codebase; not fixed here (out of scope), just noting it for whoever investigates FOUC on any of those next.
